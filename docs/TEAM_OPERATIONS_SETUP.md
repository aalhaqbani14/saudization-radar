# غرفة عمليات الامتثال المشتركة — خطوات التفعيل الأمني

> **الحالة الحالية:** الكود جاهز في المستودع، **لكن التشغيل الجماعي معطّل افتراضيًا** حتى يتم إنشاء/اختيار مشروع Supabase معتمد، تطبيق migration والتحقق من الصلاحيات. لا توضع بيانات موظفين حقيقية في المستودع العام.

## ما تم تجهيزه
- `operations.html`: متابعة محلية لا تشارك البيانات بين الأجهزة.
- `operations-team.html`: صفحة الفريق بإرسال رابط دخول للبريد، العضوية والصلاحيات.
- `assets/operations-team.js`: يتصل بقاعدة Supabase **بعد** التفعيل فقط.
- `supabase/migrations/202611110001_secure_operations.sql`: جداول الفريق، قواعد Row-Level Security، الأدوار، سجل غير قابل للتعديل عبر واجهة المستخدم، واعتمادات يراجعها **شخص آخر**.
- `data/team-ops-config.json`: إعداد تعطيل افتراضي، لا يتضمن مفتاح خادم خاصًا.
- `test_operations_team.mjs`: فحوص تحافظ على الإعداد المغلق والصلاحيات والتوثيق.

## خطوات التفعيل (مطلوبة من مسؤول حساب الشركة)

1. الحصول على موافقة المنشأة على استضافة بيانات المتابعة في Supabase من حيث الأمن والاحتفاظ وموقع التخزين. **لا تنقل مستندات أو بيانات موظفين حساسة.**
2. من لوحة Supabase إنشاء/اختيار مشروع **خاص ومعتمد**. لا تستخدم مشروعًا موجودًا لعمل آخر بدون تفويض.
3. فتح SQL Editor وتشغيل محتويات migration المذكور أعلاه بالكامل على قاعدة المشروع. إجراء الاختبارات أولاً في مشروع تجريبي.
4. ضمن Authentication إكمال إعداد خدمة إرسال رسائل البريد، وإيقاف التسجيل الذاتي قدر الإمكان، وضبط **URL Configuration** ليسمح فقط بـ:
   `https://aalhaqbani14.github.io/saudization-radar/operations-team.html`
5. إنشاء حسابات المستخدمين المسموح لهم من لوحة Authentication (دعوة إدارية مسبقة). رابط الدخول من الصفحة يستخدم `shouldCreateUser: false` فلا يُنشئ عضوية آليًا.
6. من SQL Editor (بصلاحية إدارية داخل المشروع فقط) إنشاء جهة واحدة، ثم إضافة مستخدمين مصرح لهم إلى `sradar_members`. مثال **افتراضي، لا تنفذه دون استبدال القيم الحقيقية**:

```sql
-- Run in SQL Editor as a project administrator, not in public browser code:
-- insert into public.sradar_orgs (name) values ('SALIC - Authorized Workspace') returning id;
-- insert into public.sradar_members (org_id, user_id, role, active)
-- values ('<ACTUAL-ORG-UUID>', '<APPROVED-AUTH-USER-UUID>', 'owner', true);
-- insert into public.sradar_members (org_id, user_id, role, active)
-- values ('<ACTUAL-ORG-UUID>', '<SECOND-APPROVED-AUTH-USER-UUID>', 'manager', true);
```

7. تحديث `data/team-ops-config.json` بقيم المشروع **المسموح نشرها**: `url` و`anonKey` (مفتاح **publishable/anon** فقط) و`orgId`. ضع `enabled: true` **فقط بعد** التحقق من RLS والعضويات. **ممنوع** نشر `service_role` أو `sb_secret_` أو بيانات JWT حساسة.
8. اختبار حساب صاحب صلاحية محرر وحساب مدير مستقل، وتجربة إنشاء الخطة، تعديل حالة المهمة، رفض إغلاقها قبل مراجعة الأدلة، ثم اعتمادها من **مستخدم آخر**. التأكد من منع الحساب غير العضو أو `viewer` من التعديل والاعتماد.
9. تجربة تغيير مهمة بعد اعتمادها: يجب أن يصبح اعتماد الإصدار السابق غير ساري، وتظهر المهمة بانتظار مراجعة الإصدار الجديد. افحص سجل `sradar_audit_events` من قاعدة البيانات.

## صلاحيات المستخدمين

| المستوى | الاطلاع | إنشاء/تعديل خطة | اعتماد مهمة |
|---|---|---|---|
| owner | نعم | نعم | نعم، إذا كان معتمدًا مستقلاً عن آخر محرر |
| manager | نعم | نعم | نعم، إذا كان معتمدًا مستقلاً عن آخر محرر |
| editor | نعم | نعم | لا |
| viewer | نعم | لا | لا |

مبدأ **الفصل بين المنفذ والمعتمد** مطبّق على مستوى قاعدة البيانات. كل قرار ينشئ خمس مهام عامة، ولا يحتوي على حقول أسماء الموظفين أو الملاحظات الحرة.

## اختبارات وأمان

```bash
node test_operations.mjs
node test_operations_team.mjs
node test_executive.mjs
```

- اختبار RLS الإيجابي والسلبي، والدخول البريدي، وتسجيل الأحداث **يحتاج مشروع Supabase فعليًا**؛ الاختبارات المحلية لا تعوضه.
- الموقع العام لا يكتسب سرية لمجرد وجود صفحة تسجيل الدخول: **السرية في بيانات الفريق تأتي من Auth وRLS وقاعدة Supabase**. لا تعرض تفاصيل الفريق داخل ملفات `data/*.json` العامة.
- مُدخلات الموظفين الفردية، الأجور، المستندات القانونية أو الشخصية يجب أن تبقى في الأنظمة المؤسسية المعتمدة، وليس في الغرفة الحالية.
- نتائج تقدير الفجوات في الرادار ليست تقرير امتثال قانونيًا حتى مطابقة الرموز والشروط والاعتمادات ذات الصلة.

## التحقق من النشر

بعد تشغيل GitHub Actions، افتح `/operations.html` للواجهة المحلية و`/operations-team.html` للواجهة المؤسسية. إذا كانت إعدادات الفريق مغلقة، يجب أن تظهر رسالة **«الوضع المشترك غير مُفعّل»**؛ هذا السلوك مقصود وليس خطأً.

## ملاحظة تشغيلية

الأدوار والاعتمادات وتحديد مَن يحق له رؤية/تغيير المهام قرار إداري يخص المنشأة. لا تمنح أي مستخدم صلاحية على بيانات سالك دون موافقة صاحب الصلاحية.
