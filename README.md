# Saudization Radar — رادار قرارات التوطين

منصة شخصية لمتابعة تغيرات محتملة في صفحات **وزارة الموارد البشرية والتنمية الاجتماعية**، وعرض القرارات وتحليل المهن ونسب التوطين. رصد التغييرات آلي واستدلالي، وليس ضماناً برصد كل قرار.

## تشغيل تنبيهات Gmail — ثلاثة أسرار فقط
**لا تضع كلمة مرور Gmail الرئيسية ولا كلمة مرور التطبيقات في ملفات المستودع أو في المحادثة.**

1. فعّل **التحقق بخطوتين** في حساب Gmail. ثم افتح https://myaccount.google.com/apppasswords وأنشئ **كلمة مرور تطبيق** مخصصة باسم `Saudization Radar` إن كان الحساب يسمح بذلك.
2. افتح مستودع GitHub → `Settings` → `Secrets and variables` → `Actions` → `New repository secret`.
3. أضف الأسرار التالية كلّاً على حدة:

| اسم السر | القيمة |
| --- | --- |
| `RADAR_SMTP_USER` | عنوان حساب Gmail المُرسِل (مثلاً بريدك الشخصي) |
| `RADAR_SMTP_PASSWORD` | كلمة مرور التطبيق التي أنشأتها في Google، **وليست** كلمة المرور الرئيسية |
| `RADAR_EMAIL_TO` | عنوان المستلِم؛ يمكن وضع أكثر من عنوان مفصول بفاصلة (,) أو فاصلة منقوطة (;) |

التوصيل الافتراضي: `smtp.gmail.com` على المنفذ `465` عبر TLS/SSL. إذا كانت أسرار الإعداد القديم `SMTP_USER` و`SMTP_PASSWORD` و`ALERT_EMAIL` موجودة، فإن سير العمل يدعمها أيضاً. يمكن استخدام `RADAR_EMAIL_FROM` إذا اختلف عنوان المرسِل، بشرط أن يجيزه مزود البريد.

> يمكن توجيه نسخة للبريد الشخصي وبريد الدوام بفصل العنوانين بفاصلة. لا يُنصح بإرسال معلومات موظفين أو بيانات منشأة سرية إلى هذا الموقع العام.

## اختبار إرسال رسالة الآن
1. افتح https://github.com/aalhaqbani14/saudization-radar/actions/workflows/radar.yml
2. انقر `Run workflow`، واختر فرع `main`.
3. فعّل خيار **Send a test email only** ثم انقر `Run workflow`.
4. ستظهر وظيفة `Send explicit test email`. عند نجاحها سيظهر `EMAIL_SENT: test` في سجل الوظيفة. تحقق من `Inbox` ثم `Spam` في Gmail.

**الاختبار يرسل رسالة فعلية** بعنوان يوضح أنها «محاكاة تجريبية لتغيير نسبة التوطين — ليست قراراً رسمياً»، ولا يراقب موقع الوزارة أثناء تشغيل الاختبار، ولا يدّعي وجود قرار جديد.

إذا ظهرت رسالة `Email settings missing` فأحد أسرار GitHub غير مضبوط. وإذا ظهر خطأ `535` فتحقق من كلمة مرور التطبيق أو سماح حساب Google باستخدامها.

## شكل الإشعارات المحسّن
- رسالة عربية احترافية بألوان Saudization Radar مع دعم HTML ونسخة نصية احتياطية.
- يظهر اسم المرسل **Saudization Radar** وتحتوي الرسالة على مقتطف التغيير والمصدر ورابط رسمي مباشر.
- النسب والتواريخ تُستخرج من **النص المضاف** فقط إن ظهرت فيه؛ لا يصفها النظام بأنها «قديمة/جديدة» أو «سارية» تلقائياً، حتى لا يفترض صدور قرار.
- يمكن إعادة اختبار البريد من **Run workflow → Send a test email only**. رسالة الاختبار لا تزعم وجود قرار جديد.
- أضيف فحص برمجي مستقل بدون إرسال رسائل، للتأكد من صحة تنسيق البريد وأمان المحتوى المقتبس.
- تشغيل اختبارات القالب محلياً: `python -m unittest -v test_email_templates.py`.

## مرحلة ذكاء الرصد — تصنيف إشارات القرارات
- صار التغيير يُحلل **على النص المضاف فقط** لمقارنة محتوى الصفحة بالفحص السابق؛ هذا يمنع احتساب نسبة قديمة موجودة في الصفحة على أنها تعديل جديد.
- يبحث المحلل عن **مصطلحات التوطين، صياغة القرار أو التطبيق، النسب، التواريخ ورموز المهن**.
- يحفظ الأحداث المحتملة مع **درجة أولوية للمراجعة**، وسبب تصنيفها، والمقتطف المرتبط بالمصدر الرسمي، وعلامة **«غير مؤكد — يحتاج مراجعة المصدر»**.
- **لا يرسل بريداً لمجرد ظهور كلمة «توطين»**؛ الرسالة الآلية تُرسل فقط لإشارات ذات صياغة قرار مع دليل إضافي. ولا يعني وصولها أن القرار صدر أو النسبة تغيرت.
- النصوص المعروضة تُستخرج من الصفحات العامة، وقد تكون ضمن صفحات فهرسة/أخبار لا نص القرارات الكاملة؛ يلزم مراجعة المستند الرسمي والجدول والمهن المستهدفة يدوياً.
- التحديثات التجريبية الخاصة بالانتقال من 40% إلى 60% منفصلة تماماً عن بيانات الرصد ولا تدخل جدول الأحداث الحقيقي.
- الاختبارات المستقلة: `python -m unittest -v test_detection.py test_email_templates.py`؛ لا ترسل أي بريد حقيقي أثناء تشغيلها.

## التنبيهات التلقائية
- الفحص مرتان يومياً الساعة **08:15 و17:15 بتوقيت الرياض** (05:15 و14:15 UTC)، مع احتمال التأخير حسب GitHub Actions.
- يراقب **8 صفحات رسمية** حالياً: فهرس [الأخبار](https://www.hrsd.gov.sa/media-center/news)، وفهرس [الأدلة الإجرائية](https://www.hrsd.gov.sa/knowledge-centre/decisions-and-regulations/regulation-and-procedures/evidence)، وست صفحات قرارات مختارة من سجل المصادر. هذه المراقبة لا تشمل كل قرارات الوزارة ولا محتوى PDF الكامل تلقائياً.
- عند ظهور تغيير ذي دلالة مهنية/تنظيمية يُسجَّل في قائمة المراجعة؛ ولا يُرسل إشعار إلا عند تصنيف التغيير كإشارة أقوى للمراجعة؛ ليس إثباتاً بصدور قرار.
- التشغيل الأول لمصدر جديد يحفظ خط أساس **دون إرسال تنبيه كاذب**. ولا يُرسل بريد إذا لم يُكتشف تغيير متعلق بالتوطين.
- لم يتم التحقق من إرسال البريد الفعلي إلا بعد نجاح `Send explicit test email`.

## غرفة المراجعة وصحة الرصد
- `review.html` تعرض الإشارات المكتشفة وروابط المصادر مع فلترة حسب الأولوية، ولا تعتمد أي إشارة على أنها قرار نظامي صادر.
- بعد كل تشغيل رصد ناجح يُنشئ `data/health.json` لعرض حالة كل صفحة رسمية: نجح الفحص، تعذّر الفحص، أو أُنشئ خط أساس جديد. **الصفحة لا تعرض بيانات خاصة أو كلمات مرور.**
- لا تظهر صحة الرصد في غرفة المراجعة حتى أول تشغيل طبيعي يكتب الملف؛ **الاختبارات التجريبية للبريد لا تفحص المصادر**.
- يتعرف جامع صفحات الوزارة على روابط ملفات **PDF الرسمية** وروابط الأدلة/القرارات في صفحات الوزارة؛ ولا يقرأ مضمون PDF تلقائياً.
- الإصدار 2 من استخلاص الصفحات يعيد إنشاء خط الأساس للمصادر الموجودة دون إرسال إنذار كاذب ناجم عن تغيير طريقة الاستخلاص.
- ملفات التحقق الآلي تشمل `test_monitor_health.py` إلى جانب اختبارات البيانات والقالب.
- تم إصلاح حقول تاريخية متبدّلة في سجل البريد، وتمت إعادة وسم المراجع التاريخية المستندة إلى وكالة الأنباء السعودية **للمراجعة الإضافية**، دون تقديمها على أنها تحقق نهائي من مستند القرار.

## سجل المصدر والحوكمة
- `sources.html` يعرض ستة سجلات مرجعية رسمية مع أرقام القرارات وتواريخ إصدارها ونفاذها، والحدود التي تتطلب تدقيقاً يدوياً.
- `data/source-registry.json` يحوي سجل الروابط الرسمية المتاحة للمراجعة والتوسع المرحلي في الرصد.
- **التحقق الحالي من البيانات الوصفية للصفحة لا يساوي توثيق كامل ملف القرار**؛ لا تعتمد نسباً أو مواعيد أو استثناءات دون قراءة الجداول السارية.
- يحتوي فهرس القرارات على 21 مجموعة؛ ولا يزال 17 منها موسوماً بأنه يحتاج مراجعة أعمق.
- فحص سلامة البيانات `python -m unittest -v test_data_quality.py` يتحقق من الروابط والمراجع المهنية والتواريخ والتطابق مع سجل المصدر. ويُنفّذ عبر GitHub Actions عند تغيير البيانات.
- السجل الحالي شخصي ومستقل ولا يشمل أي بيانات موظفين أو منشآت.

## أمان وقيود
المستودع وموقع GitHub Pages عامّان. تُخزن أسرار البريد في **GitHub Actions Secrets** ولا تُنشر في صفحات الموقع. لا تحفظ بيانات موظفين، معلومات داخلية، أو كلمات مرور في الملفات. قد تختلف صفحة الوزارة ديناميكياً أو تتغير دون قرار تنظيمي؛ لذلك كل إشعار هو **تغيير محتمل يجب التحقق منه من المصدر الرسمي**.

## تشغيل محلي
`python -m http.server 8000` لعرض الصفحة، و`python monitor.py` لفحص الصفحات مع اتصال إنترنت، و`python monitor.py --test-email` لاختبار SMTP عند ضبط متغيرات البيئة.
